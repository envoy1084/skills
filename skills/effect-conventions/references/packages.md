# Packages: layout, manifests, TypeScript, build, barrels

Template: `packages/opentelemetry` in the reference clone (one entry point plus per-module
subpaths, optional peers, nothing extra). For a package with directory entry points, see how
`packages/effect` exposes `effect/http`, `effect/sql`, `effect/testing`.

## Monorepo layout

```text
packages/
  <name>/                 standalone package           → @scope/<name>
  <family>/<name>/        package family (ai, sql, …)  → @scope/<family>-<name>
```

Effect flattens family paths into the npm name: `packages/atom/react` publishes as
`@effect/atom-react`, `packages/sql/pg` as `@effect/sql-pg`. Integrations with optional heavy
peers become their own package (`@effect/atom-react`) rather than a subpath of the core package.

## Files in a package

```text
packages/<name>/
  package.json
  tsconfig.json          extends the root base, include ["src"], references to workspace deps
  README.md
  CHANGELOG.md           generated by changesets
  LICENSE
  src/
    index.ts             generated barrel (see below)
    Module.ts            one public concept per file
    internal/            private implementation, camelCase files
    <area>/index.ts      optional directory entry point (e.g. src/testing/index.ts)
  test/
    Module.test.ts
  typetest/              only when compiler behaviour is under test
    Module.tst.ts
```

No per-package vitest config, no separate `tsconfig.src.json`/`tsconfig.test.json`, no
`tsdown.config.ts`: tests and type tests are type-checked by one root `tsconfig.tests.json` and run
by root configs. Justify every extra file by precedent.

## package.json

From `packages/opentelemetry/package.json` (trimmed):

```json
{
  "name": "@effect/opentelemetry",
  "type": "module",
  "version": "4.1.5",
  "license": "MIT",
  "description": "OpenTelemetry integration for Effect",
  "homepage": "https://effect.website",
  "repository": { "type": "git", "url": "https://github.com/Effect-TS/effect.git", "directory": "packages/opentelemetry" },
  "bugs": { "url": "https://github.com/Effect-TS/effect/issues" },
  "keywords": ["opentelemetry", "typescript", "functional-programming"],
  "engines": { "node": ">=22.19.0" },
  "sideEffects": [],
  "exports": {
    "./package.json": "./package.json",
    ".": "./src/index.ts",
    "./*": "./src/*.ts",
    "./internal/*": null,
    "./index": null,
    "./*/index": null
  },
  "files": ["src/**/*.ts", "dist/**/*.js", "dist/**/*.js.map", "dist/**/*.d.ts", "dist/**/*.d.ts.map"],
  "publishConfig": {
    "access": "public",
    "provenance": true,
    "exports": {
      "./package.json": "./package.json",
      ".": "./dist/index.js",
      "./*": "./dist/*.js",
      "./internal/*": null,
      "./index": null,
      "./*/index": null
    }
  },
  "scripts": {
    "codegen": "effect-utils codegen",
    "build": "tsc -b tsconfig.json && pnpm babel",
    "babel": "babel dist --plugins annotate-pure-calls --out-dir dist --source-maps",
    "check": "tsc -b tsconfig.json"
  },
  "peerDependencies": {
    "@opentelemetry/api": ">=1.9.0 <2.0.0",
    "effect": "workspace:^"
  },
  "peerDependenciesMeta": { "@opentelemetry/api": { "optional": true } }
}
```

Trimmed: the real file also has a `tags` array mirroring `keywords`, and `files` adds `AGENTS.md`,
`CLAUDE.md` and `ai-docs/**/*`, which the Effect repo copies into every package at build time.
Include those only if you adopt that AI-docs pipeline.

Rules:

- **ESM only** (`"type": "module"`), `"sideEffects": []` so bundlers can drop unused modules.
- **Exports map, two copies.** In the repository, `exports` point at TypeScript source, so
  workspace consumers and tests run without a build. `publishConfig.exports` has the *same keys*
  pointing at `dist/*.js`; pnpm swaps it in when packing. Keep the two maps aligned key for key.
- **Every module is a subpath**: `"./*": "./src/*.ts"` makes `@scope/pkg/Module` importable, which
  is how library code imports (`effect/Effect`, `@effect/opentelemetry/Resource`).
- **Block private paths** with `null`: `./internal/*`, `./index`, `./*/index`.
- **Directory entry points** get explicit keys before `"./*"`: `"./testing": "./src/testing/index.ts"`.
- **No conditions** (`development`, `source`, `types`); types come from the `.d.ts` beside each `.js`.
- **`files`** ships `src` (for source maps and go-to-definition) and the built `dist` files.
- **Peers**: `effect` is a peer dependency (`workspace:^` in the monorepo, a `^4.x` range when
  published standalone). Other peers use bounded ranges (`>=1.9.0 <2.0.0`); optional ones are
  listed in `peerDependenciesMeta`. A dependency's role is exactly one of: runtime dependency,
  peer, dev dependency.
- **Scripts per package are only `codegen`, `build`, `check`.** Tests, lint, docs and type tests
  run from the root.

## TypeScript configuration

Root `tsconfig.base.json` (verbatim options worth copying):

```jsonc
{
  "compilerOptions": {
    "outDir": "${configDir}/dist",
    "rootDir": "${configDir}/src",
    "incremental": true,
    "composite": true,
    "target": "ES2022",
    "module": "NodeNext",
    "moduleDetection": "force",
    "verbatimModuleSyntax": true,
    "allowJs": false,
    "rewriteRelativeImportExtensions": true,   // write "./X.ts", emit "./X.js"
    "erasableSyntaxOnly": true,                // no enums, no runtime namespaces, no parameter properties
    "declarationMap": true,
    "sourceMap": true,
    "strict": true,
    "exactOptionalPropertyTypes": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true,
    "stripInternal": false,                    // flipped to true only for publishing
    "skipLibCheck": true,
    "noErrorTruncation": true,
    "types": [],
    "plugins": [{
      "name": "@effect/language-service",
      "effectFn": ["untraced"],
      "namespaceImportPackages": ["effect", "@effect/*"],
      "diagnosticSeverity": { "effectFnOpportunity": "error" },
      "overrides": [{
        "exclude": ["**/internal/**/*", "**/index.ts", "**/test/**/*"],
        "options": { "diagnosticSeverity": { "apiStabilityLeak": "error" } }
      }]
    }]
  }
}
```

- Per-package `tsconfig.json`: `extends` the base, `include: ["src"]`, `references` to workspace
  packages it imports (`{ "path": "../effect" }`), extra `types` only when needed (`["node"]`).
- Root `tsconfig.packages.json` references every package; root `tsconfig.tests.json` includes all
  `test/`, `typetest/` and `benchmark/` folders with `noEmit: true` and `paths` mapping each
  package name (and `name/*`) to its `src`, so tests import packages by name.
- Root `tsconfig.json` only references `tsconfig.packages.json` and `tsconfig.tests.json`.
- `exactOptionalPropertyTypes` is why optional fields are written `?: T | undefined`.
- The language service (patched into the compiler with `effect-tsgo patch` in `prepare`) reports
  Effect diagnostics during `check`; `apiStabilityLeak` stops a stable public signature from
  exposing an unstable type.

## Build and publish

- Build is `tsc -b` (project references) followed by Babel's `annotate-pure-calls` so top-level
  calls (`dual(...)`, `Schema.Struct(...)`) are tree-shakeable. No bundler: `dist/` mirrors `src/`
  one file per module, with `.js`, `.d.ts` and both maps.
- `@internal` stripping: publishing flips `stripInternal` to `true` (`scripts/set-strip-internal.mjs`)
  so declarations tagged `/** @internal */` disappear from published `.d.ts`. That is why every
  internal export must carry the tag, and why public signatures must never mention internal types
  (lint rule `effect/no-unused-internal`).
- CI type-checks the packed declarations (`scripts/check-dist-types.mjs`) and dry-packs to verify
  the published file list.
- Releases go through changesets (see [tooling.md](tooling.md)).

## Barrels (`index.ts`)

The top of `src/index.ts` may contain hand-written re-exports; everything after a `// @barrel`
marker is generated by `effect-utils codegen` from the module files' top-level TSDoc:

```ts
/**
 * @stability unstable
 * @since 4.0.0
 */

// @barrel({Otel*,Resource}.ts): Auto-generated exports. Do not edit manually.
// NodeSdk and WebSdk are excluded because their trace SDK peers are optional;
// import them from "@effect/opentelemetry/NodeSdk" or "@effect/opentelemetry/WebSdk".

/**
 * @stability unstable
 * @since 4.0.0
 */
export * as OtelLogger from "./OtelLogger.ts"

/**
 * @stability unstable
 * @since 4.0.0
 */
export * as OtelTracer from "./OtelTracer.ts"
```

- Each entry is `export * as Module from "./Module.ts"` with the module's `@stability` and
  `@since` copied. The module's description stays in the module file.
- The marker takes an optional glob (`// @barrel({Otel*,Resource}.ts)`). Use it to keep modules
  with **optional peers** out of the root barrel; they stay importable by subpath.
- Codegen fails if a module lacks a top-level `@since`.
- `effect-utils` is private to the Effect repo. Outside it, either vendor the generator (MIT) or
  maintain the barrel by hand in exactly this format; never edit a generated section by hand in a
  repo that runs the generator.

## Outside the Effect monorepo

The Effect layout assumes its root configs. In a new repository:

- Create the root `tsconfig.base.json` (options above), `tsconfig.packages.json`,
  `tsconfig.tests.json` and `tsconfig.json` before the first package; per-package configs extend
  the base.
- `effect` is a peer dependency with a range (`"effect": "^4.1.5"`) plus a dev dependency for tests.
- Start a new package at `"version": "0.0.0"`; its first release (and every `@since` in it) is
  usually `0.1.0`, decided by the first changeset.
- Barrel codegen (`effect-utils`) is private: keep `index.ts` by hand in the generated format, or
  vendor the generator and keep the `codegen` script.

## Registering a new package (checklist)

Package work is a registration change, not a directory copy. Classify each surface and update the
applicable ones:

- workspace discovery (`pnpm-workspace.yaml` glob covers it)
- `tsconfig.packages.json` reference and `tsconfig.tests.json` `paths` for name and `name/*`
- root vitest project list, doctest `includeSource`, tstyche `testFileMatch` if it has type tests
- changeset config (fixed group / ignore list)
- CI matrices, bundle/size checks, docs and README links
- `pnpm codegen` for its barrel, then build and dry-pack (`pnpm pack --dry-run`) to inspect contents
